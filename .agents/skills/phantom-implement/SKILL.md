# Реализация PHANTOM

Для ограниченной правки начни с нужного владельца требования, существующего кода и тестов.
Для задачи по этапу используй
[сквозные gates](../../../docs/implementation-stages.md#sec-10-2), нужный этап и
[статус](../../../docs/current-status.md).

- Сформулируй наблюдаемое изменение и проверку, которая отличит исправление от прежнего
  поведения. Не пересматривай принятую архитектуру без конкретного противоречия.
- Реализуй целостное изменение в границах задания. Для SDK/I/O деталей загружай только
  соответствующий skill: `phantom-quest-development`, `phantom-ev3-development` или
  `phantom-tooling`. Не загружай весь каталог.
- Для изменения wire/IPC контракта используй `phantom-protocol-change`; для изменения
  нормативного текста — `phantom-spec-sync`. Если код догоняет существующее требование,
  требование остаётся прежним.
- Проверь исправленный сценарий и обязательные gates затронутой области. Реализуй доступные
  off-hardware части даже при отсутствии устройств; отдельно укажи недостающую физическую
  проверку. TEST, BUILD и device-фазы разделены по
  [Разработка и развёртывание](../../../docs/engineering.md#sec-8-5-1).

В результате свяжи изменение, наблюдённый результат проверок и оставшиеся ограничения.
Правила commit и защиты пользовательских изменений заданы `AGENTS.md`.

## План длительной задачи

Для многокомпонентной работы создай временный `docs/task-<TASK>-plan.md`.
Укажи результат, границы, normative owners, проверяемые шаги с checkbox,
фактические проверки и оставшиеся blockers. Пиши только сведения, нужные для продолжения;
не копируй спецификацию и raw reports. План не разрешает commit или device actions.
Долговечные решения перенеси в owning specs, незакрытые проверки — в current-status.md;
после завершения удали план. История сохраняется в Git.
