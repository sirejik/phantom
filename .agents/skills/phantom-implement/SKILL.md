# Реализация изменения

Для локальной правки найди владельца требования, существующий код и тесты.
Для задачи по этапу прочитай [сквозные условия](../../../docs/implementation-stages.md#sec-10-2),
нужный этап и [статус](../../../docs/current-status.md).

1. Сформулируй наблюдаемое изменение и проверку, отличающую его от прежнего поведения.
2. Выполни целостную правку в границах задания. Для платформенных деталей используй
   нужный навык EV3, Quest или tooling; для wire/IPC —
   [phantom-protocol-change](../phantom-protocol-change/SKILL.md), для нормативного
   текста — [phantom-spec-sync](../phantom-spec-sync/SKILL.md).
3. Для программных тестов используй [phantom-testing](../phantom-testing/SKILL.md).
   Правила исходников — в [code-guidelines.md](../../../docs/code-guidelines.md).
4. Проверь изменение и обязательные проверки затронутой области. При отсутствии
   устройств выполни доступные программные части и укажи недостающую физическую проверку.
5. Если код догнал существующее требование, обнови статус, а не требование.
   В результате свяжи изменение, наблюдённые результаты и оставшиеся ограничения.

## План длительной задачи

Для длительной многокомпонентной работы веди временный `docs/task-<TASK>-plan.md`;
небольшая правка не требует файла плана. Укажи результат, границы, владельцев,
шаги с checkbox, выполненные проверки и оставшиеся препятствия.
Не копируй спецификации и отчёты. План не разрешает commit или работу с устройствами.
Перед завершением перенеси решения в спецификации, незакрытые проверки — в статус;
удали план. Правила commit и защиты пользовательских изменений заданы `AGENTS.md`.
