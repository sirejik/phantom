# Разработка инструментов

Определи потребителя инструмента: TEST, BUILD, установка, запуск или анализ.
Проверь существующие вызовы и tests по
[каталогу скриптов и инструментов](../../../docs/python-scripts.md). Стек и команды — в
[engineering.md](../../../docs/engineering.md), языковые правила — в
[правилах кода](../../../docs/code-guidelines.md#sec-code-guidelines-tooling).

1. Различи host, device и shared runtime. Проверь версию интерпретатора и shell
   вызывающего runner, а не только среды разработки.
2. Для generator измени исходную схему/данные, пересоздай производные файлы.
   Для build/install runner сверь входы, выходы и границы операции с
   [техническими контрактами](../../../docs/engineering-contracts.md).
3. Для очистки, передачи и установки проследи containment путей и отделение outputs
   от credentials/pair state. Ошибка не должна скрываться последующим успешным шагом.
4. Проверь поведение существующим suite с временной файловой системой и подменёнными
   subprocess/network/SSH/ADB зависимостями. Lifecycle проверяй исполнением функций;
   поиск строк не подтверждает поведение. Не подключай устройства ради host-теста.
5. Для PowerShell выполни Parser API, для POSIX — `sh -n` в совместимой среде;
   синтаксическая проверка дополняет тесты исполнения. Для generator повтори запуск
   и `--check`, если предусмотрен, проверь согласованность результатов.

При отсутствии теста нужного поведения укажи пробел; успешный lint не заменяет его.
