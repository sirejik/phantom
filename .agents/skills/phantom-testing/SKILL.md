# Программные тесты

Найди проверяемое требование у владельца. Порядок и охват приёмки заданы в
[плане тестирования](../../../docs/test-plan.md#sec-9-1-2), языки и runtimes — в
[правилах кода](../../../docs/code-guidelines.md). Не составляй каталог автоматических
cases в документации: конкретные сценарии принадлежат suites.

## Выбор сценариев

- Unit tests проверяют алгоритм/компонент, functional tests — наблюдаемое поведение
  через реальные входы и выходы. Проверяй взаимодействие production-компонентов на PC.
- Для каждой функции выбирай штатные, негативные и граничные сценарии, переходы состояний,
  таймауты, отказы зависимостей и восстановление, где применимы. Воспроизводимый дефект
  закрепи регрессионным тестом, выявляющим ошибку до исправления.
- Assertions проверяют требуемые state/output, допустимость действий и побочные эффекты.
  Проверка «не упало» и копия вычисления из реализации не доказывают правильность.
- Coverage используй для поиска пробелов. Проверь assertions сгенерированных тестов
  и фактически выполни их.

## Изоляция оборудования

Тестируй поставляемый код; fake/mock заменяют I/O, SDK, сеть, часы и platform services.
Делай время и инъекции отказов детерминированными, без движения моторов, надетого Quest
и ожидания длинных реальных таймаутов.

| Область | Способ проверки |
|---|---|
| EV3 core/controller/safety | Host-native tests с MockMotorBackend/fake I/O; assertions на запреты выхода и переходы состояний |
| EV3 network/mDNS | Host tests с управляемыми IPC/network/process зависимостями |
| Quest logic/adapters/UI | EditMode/PlayMode с fake SDK observations и lifecycle; это среды исполнения, а не типы тестов |
| Android bridge | Java/C# tests wrappers, ошибок и освобождения ресурсов; фактический Android runtime проверяется интеграционно |
| Quest↔EV3 | Production client/network interop, общие golden/negative vectors; stub не заменяет shipped компоненты |

Тесты продукта запускай через `python tooling test --target ev3/quest`.
При переносе реализации между языками сохрани сценарии регрессий и проверь новый код;
старый suite не доказывает её. Запусти затронутые suites и линтеры. Укажи команды,
результаты и непроверенное поведение; host PASS не подтверждает работу устройств.
