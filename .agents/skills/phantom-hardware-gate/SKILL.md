# Работа с устройствами

Сопоставь запрос с операцией из
[engineering.md](../../../docs/engineering.md#sec-8-5-1) и используй существующий runner.
Выполни уже порученные операции; не добавляй provisioning, тестирование или запуск
как скрытый шаг. Недостающий prerequisite останавливает зависимую операцию,
но не доступную подготовительную работу.

1. Определи назначенную пару, профиль, кандидат и применимые сценарии. Сверь фактическое
   устройство и identities с входами runner и
   [техническими контрактами](../../../docs/engineering-contracts.md).
2. Для интеграционных тестов проверь
   [пререквизиты](../../../docs/test-plan.md#sec-integration-prerequisites): Quest неподвижен
   и не надет, EV3 без допуска движения. Suspend не обходится датчиком присутствия;
   недоступный case отмечается согласно плану тестирования.
3. Для ручных тестов используй [подготовку](../../../docs/test-plan.md#sec-test-plan-prerequisites)
   и сценарии плана. Перед движением проверь применимые
   [условия безопасности](../../../docs/safety.md#sec-11-4).
4. Выполни операцию штатным runner с timeout, сохрани первый отказ и прекрати зависимые
   действия. Автоматические результаты обрабатываются по
   [метрикам и отчётам](../../../docs/metrics-and-logs.md). Не требуй заполнения ручного
   отчёта, если его не предусматривает порученная работа.

При missing/corrupt credentials или pair state не выполняй скрытую ротацию/repin;
работай по правилам подготовки устройств. Если оборудования нет, оставь проверки
NOT_RUN и укажи действие для продолжения. Не заявляй ненаблюдавшийся PASS.
